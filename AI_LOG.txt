
## Kiinduló prompt

> Készíts egy reszponzív, magyar nyelvű React + TypeScript + Vite prototípust kitalált tranzakciók, kategóriák és költségkeretek követéséhez. Lehessen új kiadás és kategória szerinti összeget felvenni egy tranzakciólistába. Az adat maradjon meg oldalfrissítés után localStorage használatával. Ne készíts backendet vagy valódi bejelentkezést.

Indítás:

npm install
npm run dev

## Refaktor napló

### 2026-10-01
- A korábban egyetlen fájlban lévő alkalmazást külön App, komponens, domainadat-, típus- és tárolási modulokra bontottam.
- A localStorage betöltése most ellenőrzi a JSON szerkezetét és a tranzakció/kategória/keret mezőit; hibás vagy hiányos adat esetén használható kezdőadatokat ad.
- A tárolási hibák nem állítják le az alkalmazást, így a felület memóriában tovább használható.
- Az űrlapok natív validációt, szöveg-hosszhatárt és trimelt adatfelvitelt kaptak; a modális Escape billentyűvel és bezáró gombbal is bezárható.
- A dátum alapértéke helyi dátumból készül, a tranzakció dátumának megjelenítése pedig elkerüli az UTC miatti előző napra csúszást.
- A navigáció szemantikusabb lett, az aktív oldal jelölést kapott, a még nem működő Beállítások elem pedig letiltott állapotú.
- Az HTML dokumentum magyar nyelvet, reszponzív viewportot, leírást és FinTrack címet kapott.
- A README kiegészült a forrásfájlok szerepének rövid áttekintésével.
- A projekt fejlesztői függőségei kiegészültek a React típuscsomagokkal, a Vite környezeti típusdeklaráció pedig lehetővé teszi a CSS-import TypeScript-ellenőrzését.
- Ellenőrzés: `npm run build` sikeres (TypeScript és Vite production build).

## Backend implementációs napló

### 2026-10-09
- Külön .NET 10 ASP.NET Core Minimal API projekt készült EF Core és Npgsql használatával, PostgreSQL-adatbázishoz.
- Elkészült a kategória-, tranzakció- és költségkeret-adatmodell, kategóriaidegen kulcsokkal; migráció kezdeti sémával és hat alap-kategóriával, négy havi kerettel.
- API-végpontok készültek a tranzakciók és kategóriák listázására/létrehozására, kategóriák idempotens importjára, valamint költségkeretek lekérésére és módosítására.
- A frontend már API-ból tölti az adatokat; mentési hiba esetén nem frissül sikeresnek látszó állapotra. A költségkeretek szerkeszthetők.
- A korábbi localStorage-kategóriák egyszer importálódnak, a korábbi tranzakciók nem kerülnek át.
- A Vite `/api` proxy, PostgreSQL indítási útmutató és ASP.NET fejlesztői indítóscript elkészült.
- Ellenőrzés: `dotnet build`, `npm run build` és az EF `InitialCreate` migráció generálása sikeres.
- HTTP füstpróba: a frontend 200 választ adott, a Vite proxyn keresztüli API health `ok`, a hibás tranzakciókérés 400 választ kapott.
- Az adatbázis-migráció tényleges futtatása és a sikeres DB-olvasás/írás ellenőrzése nem volt lehetséges, mert nincs helyi PostgreSQL-szolgáltatás vagy Docker a környezetben.

### Helyi PostgreSQL bekötés – 2026-10-09
- A PostgreSQL 18 szolgáltatás elérhetővé vált, a `fintrack` adatbázishoz tartozó kapcsolat a .NET User Secrets tárolóba került; jelszó nem került forrásfájlba.
- Az `InitialCreate` migráció sikeresen lefutott, és az EF migrációlistája alkalmazottnak jelzi.
- PostgreSQL-en ellenőrizve: hat kategória, négy költségkeret; a keret frissítése és visszaolvasása sikeres.
- Kategória és tranzakció API POST/GET próbája sikeres volt; az ideiglenes próbasorokat eltávolítottam.
- A Vite proxyn át a health `ok`, az alapadatok betöltődnek; a fejlesztői API és frontend szerver fut.
